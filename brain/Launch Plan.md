## Phase 1 — The test account (weeks 1–4)

**The model (founder direction, 2026-08-01): a realtor's page, translated to solar.** The archetype: face-first local expert — the person IS the brand, the market data is the proof. Every element maps cleanly:

| Realtor page | This account |
|---|---|
| Market update posts ("Phoenix housing this month") | Rate/APS-news cards from the editorial engine (DESERT GRID becomes the *market-update pillar*, not the spine) |
| "Just sold" / closing-day posts | "Just installed / just saved" posts — real jobs, real permissioned numbers only |
| Community & neighborhood spotlights | Valley community spotlights (heat, growth, energy angle) |
| Personal/lifestyle (family, day-in-the-life) | The photo dump lane — Taylor, truck, rooftops, desert |
| Buyer tips | Home-energy and solar-decision tips |

**Grid re-weighting under this model:** flip the mix face-forward — roughly **45% personable/lifestyle/story, 30% market-update educational (designed cards), 25% proof-of-work** — and push the grid's photo-feel:designed-card balance from ~2:1 toward **~3:1**. The founder's face or a real photo should be the first thing a profile visit sees. Educational cards still carry the authority; they're seasoning, not the meal. Everything else in this plan (Phase 0 steps, cadence, Sunday loop, compliance rules, Phase 2) is unchanged by this pivot — the built editorial system keeps running as one pillar instead of the whole page.

**Cadence (playbook interim — sustainable for one person): 1 reel + 2 carousels per week + a daily 3-minute Story.** Do not attempt the spec's full 3-reel target until this holds for 4 straight weeks. Consistency beats volume.

**Content ratio:** superseded by the realtor-page model above (45/30/25 face-forward); the original editorial-spine weighting (~40% rising-prices led) remains the fallback if the personable lane runs dry — which nets out near the research's thirds. In practice: **roughly 1 personable post for every 2 educational posts**, hard sales confined to at most 1-in-5 posts.

## Phase 2 — Productization (weeks 4–12)

**Plain statement first:** the audit found four blockers — no auth, cosmetic tenancy, one open wallet, no billing. **Selling access before these are fixed would break:** a stranger's first curl can burn your Higgsfield/ElevenLabs/Anthropic budget, and any customer can read, overwrite, or delete any other customer's media and CRM PII. No customer money changes hands until steps 2–4 below are accepted. Dependency order is fixed; do not reorder.

**Step 1 — Ship the real product to main (weeks 4–5). Owner: Taylor (+ Claude Code). Tools: git, GitHub, Vercel.**
The demo-able product — the entire Higgsfield video lane, voice cloning, ffmpeg assembly, media vault, News Desk — lives in `claude/app-performance-max-h8tgoc`, **31 commits ahead of origin/main, unmerged**. Merge it via PR. Then untangle the repo: farmhand is a subdirectory of a mixed personal repo (Coyote & Company landing page at root, untracked `agency-os/`, an unrelated pharma branch). Extract farmhand to its own repo (or make it the repo root) with its own Vercel project.
- *Acceptance:* production URL runs the full reel pipeline from main; `git status` clean; no unrelated branches; local checkout is not a stale ancestor.

**Step 2 — Authentication (weeks 5–6). Owner: Taylor (+ Claude Code). Tools: Clerk or Supabase Auth, Next.js middleware.**
Today there is no login, no session, no user record; the one "token" gate is `NEXT_PUBLIC_REEL_JOB_TOKEN`, compiled into the public bundle. Add real auth and a `middleware.ts` requiring a session on **every** `/api/*` route before anything else runs. Remove the NEXT_PUBLIC token entirely.
- *Acceptance:* unauthenticated curl to `/api/higgsfield`, `/api/tts`, `/api/copy`, `/api/vault`, `/api/memory` each returns 401; the founder can sign in and everything still works.

**Step 3 — Real tenancy (weeks 6–8). Owner: Taylor (+ Claude Code). Tools: Supabase (Postgres + RLS), Vercel Blob.**
Clients are currently localStorage labels; every route trusts a caller-supplied `client`/`workspace` string, Blob objects are public with deterministic keys, and `/api/memory` serves any workspace's PII via a service-role key. Make workspaces DB rows owned by authenticated users; **every route derives the workspace from the session, never from the request body**; Blob access scoped or signed.
- *Acceptance:* an automated test where user A attempts to list, fetch, and delete user B's vault and memory — all three fail; Taylor's own multi-client operator mode still works under his one login.

**Step 4 — Server-authoritative metering + rate limits (weeks 8–9). Owner: Taylor (+ Claude Code). Tools: Upstash (already in stack), per-route checks.**
The only cost guard is `lib/meter.ts` — a client-side localStorage ledger the code itself calls "E7-era." Move quota enforcement server-side, inside each route, **before** any provider call; add per-account rate limits; log per-tenant provider spend.
- *Acceptance:* clearing localStorage restores nothing; an over-quota generation request returns 429 server-side; you can answer "what did tenant X cost me this month" from logs.

**Step 5 — Durable persistence (weeks 9–10). Owner: Taylor (+ Claude Code). Tools: Supabase sync (already scaffolded in `supabase/schema.sql`, currently inert).**
The system of record is one browser profile; a full localStorage quota silently drops data. Turn on and extend the Supabase memory layer so contacts, opportunities, planned posts, strategy, and asset indexes survive the browser.
- *Acceptance:* sign in from a fresh browser and the full workspace is there; kill localStorage mid-session and nothing customer-facing is lost.

**Step 6 — Billing (weeks 10–11). Owner: Taylor. Tools: Stripe subscriptions + webhooks.**
Zero payment code exists; "Territory tier = 60 images" is aspiration in a constant. Wire Stripe: plan tier drives the Step-4 server quotas; paywall on workspace creation (a free trial is fine, but the gate exists).
- *Acceptance:* test-mode subscribe raises the quota, cancel lowers it, all via webhook with no manual step; a stranger can go card-to-quota with no founder involvement.

**Step 7 — Stranger-proof onboarding (weeks 11–12). Owner: Taylor. Tools: the app itself + 2 outside testers.**
Signup → brand setup (colors, territory, vertical) → first generated post, with no founder in the loop.
- *Acceptance:* two people who have never seen the app each go from signup to an exported post in under 30 minutes, unassisted, on their own dime (metered).

**Step 8 — First 3 paying customers (week 12). Owner: Taylor. Tools: the test account, the app's own lead engine, DMs.**
The demo is not a pitch deck — it is **@taylorlucesolar's before/after**: 1 reel and a lifestyle grid on day 0 vs a publication-grade grid, produced reels in his own cloned voice, and the metrics log from the weekly loop. Motion:
1. Pull 20 prospects from the app's own lead engine — Phoenix-area **realtors** (a supported vertical) and non-competing local home-service operators.
2. DM/email 10 with a 3-line note + the account link: "this grid is 12 weeks old and made by the tool."
3. Offer a **founding price** (anchor off real per-tenant cost from Step 4 — margin is now known, not a browser variable), white-glove onboarding call included.
4. Close 3. Their accounts become case studies 2–4.
- *Acceptance:* 3 Stripe subscriptions live, each customer past first-post onboarding, zero cross-tenant incidents.

## Metrics that matter (weekly, Sunday loop, all from the IG app on the phone)

1. **Posts shipped vs planned (x/3)** — consistency is the whole game; below 3 two weeks running, cut scope, not the streak.
2. **Non-follower reach % on reels** (Insights → per-reel) — is discovery working on cold Phoenix audiences.
3. **Saves + sends per post** — the top ranking signals post-Dec-2025, and the truest "was this useful" measure.
4. **Follower count + profile visits** — is discovery converting (baseline: 133).
5. **Inbound DMs from keyword CTAs** — the only number that eventually pays for anything.

## Rules (binding — one line each)

1. On any conflict, the spec wins: `farmhand/docs/content-engine-spec-2026.md` is canonical.
2. Grey the field, color the subject: ACCENT_HOT means "this costs you money," ≤15% of pixels, once per slide, never decorative.
3. One post = one argument; one number per slide, isolated as number–unit–qualifier.
4. Source line on every numbered slide — exact sourced numbers ARE the personality.
5. On-screen text is a summary (≤~12 words/slide); the education lives in the caption — posts must never look educational.
6. Every post must survive cutting 30–40% of its text; cover 6–12 words, chart slides ≤35.
7. Lane 3 proof-of-work uses real photos only; AI imagery is generic illustration, never fake jobs or fake customer results.
8. Disclose AI: toggle "AI info" on meaningfully AI-edited posts; never strip metadata to dodge labels.
9. Voice: a sharp local who knows the numbers, plain 8th-grade second-person; the honest "not yet" is the brand.
10. Build the pain, never soothe it; pro-solar, honestly anti-rate-design, VPPs framed as proof of strain — never "the grid is unstable."
11. Be realistic about costs and savings always — it is the number-one trust factor and the anti-door-knocker positioning.
12. At most 1-in-5 posts carries an offer; keyword-DM CTAs on ≤20% of posts; the conversion object is always a useful asset.
13. No two same-look posts adjacent; the grid must pass a 2-second credibility scan — ~3:1 photo-feel to designed-card under the realtor-page model (founder direction 2026-08-01; supersedes the spec's ~2:1).
14. Nothing publishes without a fact-check receipt against the KB; perishable news items get re-verified before use.
